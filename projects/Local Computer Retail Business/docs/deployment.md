# Local Computer Retail Business — Deployment

A high-level, sanitized overview of how the system runs in production. Specific server addresses, credentials, client identity, and provider account details are intentionally omitted.

---

## Topology

A two-tier deployment: a static React frontend and a Node/Express API, both hosted on infrastructure appropriate for a small-business retail environment.

```
                ┌────────────────────────┐
```

## Process Supervision

The Express API runs under **PM2** in cluster mode for resilience and zero-downtime reload on deploy. PM2 is supervised by systemd so it survives host reboots without manual intervention.

| Process | Purpose | Supervisor |
|---------|---------|------------|
| **Express API** | Handles all REST traffic, auth, business logic | PM2 → systemd |
| **Nginx** | TLS termination, reverse proxy, static asset serving | systemd |

## Database Strategy

- **Production** — PostgreSQL with managed backups
- **Development** — SQLite for fast local iteration with no host services to install
- **Schema** — managed via **Prisma migrations** so dev and prod stay in lockstep

The dev/prod database split is intentional: it keeps the local developer experience friction-free while production gets a real database with concurrency guarantees.

---

## Build & Deploy

The frontend is built once via **Vite** and served as static assets directly by Nginx. The backend deploys via a build artifact pushed to the host, after which PM2 performs a graceful reload — no dropped requests during deployment.

Database migrations run via `prisma migrate deploy` as part of the deployment script, gated to prevent accidental destructive changes in production.

---

## Backups & Recovery

- **Database** — nightly logical backups shipped off-host with a retention window appropriate for the client's compliance and operational needs.
- **Receipts and exports** — files generated by the system (Excel reports, receipt PDFs) are written to a path that participates in the backup rotation.
- **Restore drills** — periodic restore tests validate backup integrity end-to-end.

---

## Security Hardening

- **Helmet** sets standard security headers on every API response.
- **Express Rate Limit** throttles login and other sensitive endpoints to slow brute-force attempts.
- **CORS** is locked to known frontend origins; nothing else can call the API from a browser.
- **JWT** access tokens are short-lived; refresh rotation prevents replay.
- **bcryptjs** hashes all stored credentials.
- **Multer** file uploads are size-capped and type-restricted.

---

## Observability

- **Sentry** — production error tracking for both frontend and backend with full request context.
- **Pino** — structured JSON application logging written to disk and rotated.
- **Health checks** — a lightweight `/health` endpoint probed by the host's monitoring.
